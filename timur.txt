
Версию Java лучше не ставить пока 25, а понизить до 21, чтобы было меньше сюрпризов для связки spring + библиотеки (причем эти ошибки могут быть плавающие), в общем пока можно просто иметь это в виду

Подключить swagger - он создаст контракты (описание RESTful) и нужен будет для тестирования

Адреса, порты, токены - лучше выноситть в настройки, которые подтягиваем через config
Пример нежелательного хардкода this.webClient = webClientBuilder.baseUrl("http://localhost:8765/parser/api").build();

@Async желательно добавить параметр для пула в файле yml, пример
core-size: 4
max-size: 8
queue-capacity: 100
Чтобы не разрасталось бесконечно (это требования из документаций)


WebClient + .block() - это синхронный вариант, поэтому желательно добавить таймауты и retry (повторная попытка), это одно из требований по правильному функц коду если используется block
либо перейти на subscribe, чтобы был асинхронный код

Во всех бразурах проверить, что при logout удаляются токены из куков (в браузере открывать хранилище и смотреть)


Добавить режим debug - т.е. чтобы для основных действий (начало-конец) - были подробные логи с указанием метки времени - чтобы видеть тайминги под нагрузкой (принцип кто/что/когда)
И это обязательно реализовать через Spring AOP (чтобы вручную не править код во всех местах) - он сам после запуска подставит код логирования в нужных местах кода

Можно сделать unit тесты для каждой важной функции - входные параметры и ожидаемый результат (т.е. тестировать не кнопки, а именно отработка функций, куда уже приходят нужные параметры для проверки и какой результат мы ожидаем)

Затем провести нагрузочное тестирование (именно бекенда, который вызывает тг), чтобы выявить таймауты и слабые места с включенным debug режимом (описан выше) - это отделбно обсудим как лучше сделать
